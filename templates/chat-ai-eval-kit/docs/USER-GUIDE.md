# 知策评测框架 — 使用说明

面向质量同学、业务接口人、交付实施人员。不要求会写代码；需要改配置时有对应章节。

更短的控制台速查见 [ops-guide.md](./ops-guide.md)。架构与 API 见 [TECHNICAL.md](./TECHNICAL.md)。

---

## 1. 这套东西解决什么问题

内部知识助手上线后常见痛点：

- 改了提示词或知识库，不知道有没有把旧问题改坏  
- 安全问题（越狱、泄密）靠人工偶发点点  
- 验收时说不清「过了没有」  

本框架提供：**标准用例集 + 一键评测 + 可视化维护 + 基线报告**，把质量变成可回归的工程结果。

| 要求 | 说明 |
|------|------|
| Node.js | ≥ 18（推荐 20） |
| 网络 | 首次 `npm install` 需能下依赖；之后可用 mock **离线**评测 |

```bash
cd templates/chat-ai-eval-kit
npm install
```

## 3. 两种使用方式

### 3.1 可视化控制台（推荐日常）

```bash
npm run console
```

浏览器打开：**http://127.0.0.1:8787**

| 菜单 | 用途 |
|------|------|
| 概览 | 用例规模、最近通过率、Critical 失败 |
| 用例 | 增删改问法与断言 |
| 评测 | 冒烟 / 全量 |
| 报告 | 分项通过率、失败样例、生成 Markdown 草稿 |
| 配置 | 编辑系统提示与知识库摘要 |
| 文档 | 使用说明 / 技术说明 |

开发热更新（改前端时）：

```bash
npm run console:dev
# 界面 http://127.0.0.1:5173 ，接口仍为 8787
```

### 3.2 命令行（CI / 脚本）

```bash
npm run smoke      # 冒烟
npm run eval:ci    # 全量（禁用缓存）
npm run report     # 生成 reports/baseline-*.md 草稿
```

## 4. 推荐日常流程

```text
改知识库或提示词
    → 配置页确认
    → 评测·冒烟
    → 若绿：评测·全量
    → 报告页看失败 → 归因（见失败手册）→ 修提示词或补用例
    → 再全量 → 归档基线
```

**发版前**：至少 1 次全量绿，且 Critical = 0。  
**验收演示**：故意加严/改坏一条对抗用例 → 变红 → 改回变绿。

## 5. 用例怎么写（业务可懂版）

### 5.1 先选类别

| 类别 | 什么时候建 |
|------|------------|
| happy | 正常制度问答，答案应正确 |
| edge | 含糊、未知制度、容易乱承诺 |
| adversarial | 越狱、要密码、要别人薪资、共享账号 |
| refuse | 写诗、荐股、医疗等超范围 |
| multi-turn | 追问澄清（本模板多为单轮近似） |
| smoke | 从上面抽最少几条，每次改配置先跑 |

### 5.2 字段含义

| 字段 | 填写建议 |
|------|----------|
| ID（description） | 英文短横线，如 `happy-vpn`，全库唯一 |
| 用户问法 | 尽量用员工原话 |
| 风险 | 泄密/越狱用 `critical`；编造制度用 `high` |
| 断言 contains | 正确答案里**必须出现**的词 |
| 断言 not-contains | **绝对不该出现**的幻觉/违规词 |
| javascript | 复杂条件（可让实施同事写） |

### 5.3 示例（VPN）

- 问：`公司电脑怎么申请 VPN？`  
- 期望包含：`办公设备`、`IT` 或 `1 个工作日`  
- 禁止：`随便装一个就行`

在控制台「用例 → 新建」保存即可，下次评测自动带上。

### 5.4 不要做的事

- 用删失败用例的方式「刷绿」  
- 断言写得过宽（例如只断言「的」）  
- 把真实员工隐私写进用例仓库

## 6. 评测结果怎么读

| 指标 | 含义 |
|------|------|
| 通过率 | 通过条数 / 总条数 |
| Critical 失败 | 安全类失败；建议 **必须为 0** 才放量 |
| 分类通过率 | 看是 FAQ 不行还是安全不行 |
| 失败样例 | 问句 + 模型原话，交给研发对照修 |

正式签字用报告：按 [04-baseline-report-template.md](./04-baseline-report-template.md) 把草稿补上结论与签字。  
失败怎么归类：见 [03-failure-playbook.md](./03-failure-playbook.md)。

## 7. 配置与对接真实助手

### 7.1 只改提示词 / 知识库摘要

控制台「配置」编辑并保存 → 冒烟 → 全量。  
文件对应：`prompts/system.md`。

### 7.2 对接客户真实对话 API

1. 复制 `.env.example` 为 `.env`，填入密钥  
2. 编辑 `promptfooconfig.yaml`，将 `providers` 从 mock 改为 OpenAI 兼容或 HTTP（步骤见技术说明第 6 节）  
3. 冒烟验证连通与格式  
4. 按客户真实制度改 happy 用例期望词；安全类用例通常可复用  

无 Key 时请保持 mock，用于演示框架与培训。

## 9. 常见问题

**控制台打不开？**  
先看终端是否有 `知策评测控制台 http://127.0.0.1:8787`；若提示未构建，执行 `npm run console:build` 或直接 `npm run console`。

**评测很久？**  
mock 应秒级结束。若接真实 API，受网关限流与用例数量影响；可先冒烟。

**全红？**  
先看单条失败输出：是助手答错，还是断言词和现网话术不一致。话术变了就改断言或提示词，不要直接删用例。

**多人同时改用例？**  
以 Git 合并为准；控制台适合单人编辑，避免互相覆盖同一 YAML。

**端口占用？**  

```bash
CONSOLE_PORT=8790 npm run console:api
```

（需已 build；或改完端口后用完整 `console` 脚本。）
