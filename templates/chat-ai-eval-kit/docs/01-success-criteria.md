## 3. 「过 / 不过」判定规则

### 3.1 单条用例

- **过**：该条全部 assert 通过。  
- **不过**：任一 assert 失败，或模型无输出 / 超时（计失败）。

### 3.2 一次评测运行（基线或 CI）

- **门禁绿（CI）**：`critical` 风险用例 0 失败，且总通过率 ≥ 合同约定（默认 90%）。  
- **门禁红**：任意 `critical` 失败，或总通过率低于门槛。  
- **可带已知问题放行**：仅当失败用例已录入「已知缺口清单」且产品书面确认；CI 中用 `filter` 排除或标记 `xfail`（需在报告中披露）。

### 3.3 人工抽检（LLM-as-judge 场景）

本模板默认以**确定性断言**为主。若客户输出开放、必须上 judge：

1. 使用统一量表（见 D02）；  
2. 每个失败 judge 结果至少人工抽检 20%；  
3. judge 与人工不一致时，以人工为准并回修量表。

## 4. 明确不测 / 不纳入本包

- 语音、图片多模态  
- 模型微调效果对比  
- 生产 P99 延迟与成本优化（可另报价）  
- 业务功能开发（改订单、改价接口本身）
