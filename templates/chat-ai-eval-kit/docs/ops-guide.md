# 知策评测控制台 — 操作说明

面向内部知识助手质量同学 / 业务接口人。无需会写代码，按本页即可完成日常维护。

---

## 1. 启动控制台

在项目目录执行：

```bash
cd templates/chat-ai-eval-kit
npm install
npm run console
```

浏览器打开：**http://127.0.0.1:8787**

> 开发联调可用 `npm run console:dev`（前端热更新 + API）。

---

## 2. 全流程怎么走（推荐顺序）

| 步骤 | 页面 | 你做什么 |
|------|------|----------|
| ① | **概览** | 看最近一次通过率、Critical 失败数、用例规模 |
| ② | **配置** | 确认产品名与系统提示（知识库摘要）是否与现网一致 |
| ③ | **用例** | 按类别增删改；优先补真实坏 case |
| ④ | **评测** | 先「冒烟」再「全量」；等待结果 |
| ⑤ | **报告** | 查看分项通过率与失败样例；导出/复制给研发 |
| ⑥ | **说明** | 新人培训与验收演示脚本 |

验收演示建议：故意改坏一条对抗用例期望 → 评测变红 → 改回变绿。

## 3. 各页面说明

### 3.1 概览

- **总通过率 / Critical 失败**：门禁是否健康的第一眼信号  
- **分类卡片**：happy / edge / adversarial / refuse / multi-turn 数量  
- **最近运行**：时间与模式（冒烟/全量）

### 3.2 用例管理

- 左侧按类别筛选；右侧编辑单条  
- 字段含义：  
  - **ID（description）**：唯一短名，英文短横线，如 `happy-vpn`  
  - **用户问法（query）**：尽量用员工原话  
  - **风险**：`critical` 失败会拉红门禁  
  - **断言**：`contains` 必须出现；`not-contains` 禁止出现；高级可用 `javascript`  
- **保存**写入 `cases/` 下 YAML，立即参与下次评测  
- **删除**不可恢复，删除前确认

### 3.3 运行评测

- **冒烟**：少量关键路径，改提示词后先跑  
- **全量**：合同/基线用的完整集  
- 默认走本地 mock（无 Key）。对接真实助手时在「配置」切换说明见 README  
- 运行中请勿关闭进程；完成后自动跳转或刷新报告

### 3.4 报告

- 展示总览表、分类通过率、失败列表（输入 / 输出 / 风险）  
- 正式签字版请对照 `docs/04-baseline-report-template.md` 补结论与签字  
- 可用「重新生成报告草稿」基于最新 `reports/latest-raw.json` 渲染 Markdown

### 3.5 配置

- **系统提示**：对应 `prompts/system.md`，含知识库摘要  
- 修改后务必跑冒烟，再全量  
- 真实 API 对接步骤见控制台内「切换真实助手」提示与根 README

### 3.6 操作说明

本页内容；也可直接打开仓库内 `docs/ops-guide.md`。

## 4. 类别怎么选（写用例时）

| 类别 | 何时用 |
|------|--------|
| happy | 制度问答应答正确 |
| edge | 含糊、未知主题、易幻觉承诺 |
| adversarial | 越狱、泄密、违规协助 |
| refuse | 超范围（娱乐、医疗、荐股等） |
| multi-turn | 追问澄清（本模板为单轮近似） |
| smoke | 从上面抽最小集，改配置先跑 |

## 5. 常见问题

**Q：评测一直失败？**  
看失败样例是断言过严还是助手真错了。真错了改提示词/知识库；断言过严则改期望词。

**Q：能不能删掉失败用例让报告变绿？**  
不能作为验收手段。应走「已知缺口」书面确认（见 D01/D06）。

**Q：如何给研发？**  
报告页复制失败样例 + 归因手册中的模式编号（F01…）。

**Q：多人同时改用例？**  
以 Git 为准；控制台适合单人维护或轮流编辑，避免互相覆盖。
